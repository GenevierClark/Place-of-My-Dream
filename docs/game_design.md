# 게임 기획 문서

> 이 문서는 Gemini와의 기획 논의를 바탕으로 계속 갱신되는 최신 기획본입니다.
> 논의 히스토리는 [devlog.md](./devlog.md) 참고.

## 1. 프로젝트 개요

- 장르: 턴제 로그라이크 (노드 탐색형)
- 개발 환경: C++, Windows Console API
- 개발 기간: 30일 (여름 집중 포트폴리오 프로젝트)
- 핵심 내러티브: 플레이어는 꿈속 무의식의 세계를 탐험하며 잊혀진 '기억의 파편'을 찾아 더 깊은 심연(다음 맵)으로 나아간다. 수면 심도가 다하여 꿈에서 깨기 전에 목적지에 도달해야 한다.

## 2. 개발 및 설계 목표 (포트폴리오 포인트)

이 프로젝트는 단순한 콘솔 게임 제작을 넘어, 게임 클라이언트 프로그래머로서의 탄탄한 C++ 기본기를 증명하는 것을 목표로 한다.

- 객체지향 설계 (OOP): 다형성을 활용한 유연한 노드(방) 및 엔티티(몬스터, 플레이어) 클래스 구조 설계.
- 자료구조 활용: 노드 간의 연결 상태를 구현하기 위한 그래프(Graph) 활용.
- 상태 관리 (State Machine): 턴제 전투 흐름 및 맵 탐색 씬(Scene) 전환의 깔끔한 제어.
- 데이터 캡슐화: '수면 심도', 'HP' 등 플레이어의 핵심 데이터를 캡슐화하고 외부(이벤트, 피격 등) 환경 변화에 유기적으로 반응하는 구조(옵저버 패턴 등) 구현.

## 3. 핵심 게임 루프 (Core Game Loop)

1. 진입: 특정 수치의 '수면 심도(Sleep Depth)'를 가지고 Map 1에 진입.
2. 탐색 (선택의 딜레마):
   - 인접한 미지의 방으로 이동 (수면 심도 소량 감소, 리스크 감수).
   - 인접한 방 정찰 (수면 심도 대량 감소, 안전/정보 확보).
3. 이벤트 발생: 입장한 노드의 타입(전투, 휴식, 상점)에 따른 상호작용.
4. 돌파: 맵 어딘가에서 '열쇠'를 획득한 뒤, '잠긴 문' 노드를 통해 다음 층으로 이동.
5. 종료 조건:
   - 승리: 총 5개의 Map을 모두 클리어.
   - 패배: HP가 0이 되거나, 수면 심도가 0이 되어 꿈에서 깨어남.

## 4. 시스템 기획 세부사항

### 4.1. 맵 (Map) 시스템

- 구조: 플레이어가 선택지를 통해 이동하는 노드(방) 형태. 뒤로가기가 가능한 탐색형 구조.
- 정보 해금 (Fog of War): 초기 맵 진입 시 연결된 방의 존재만 확인 가능. 방의 내용물은 `[ ? ]` 상태로 출력되며, 유저의 '정찰' 액션을 통해서만 텍스트/UI 정보가 갱신됨.

### 4.2. 노드(방)의 종류

모든 방은 기본 `Node` 클래스를 상속받아 구현된다.

1. 휴식처 (Rest Room): 진입 시 플레이어의 HP 혹은 수면 심도를 회복. 1회 사용 후 빈 방으로 전환.
2. 전투방 (Combat Room): 일반 몬스터와 조우. 승리 시 재화 혹은 경험치 획득. 턴제 전투 시스템으로 전환.
3. 상인의 방 (Merchant Room): 획득한 재화를 소모하여 스탯 증가(최대 HP 등) 혹은 소비형 아이템(수면 심도 회복제 등) 구매.
4. 잠긴 문 (Locked Exit): 다음 Map으로 가기 위한 출구. '열쇠' 인벤토리 확인 로직을 거침.
